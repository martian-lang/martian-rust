Create a new martian rover with the files path and the resources Rover needs to know the resources explicitly, so none of the resource fields shoulbd be empty when invoking this function.

pub fn make_path<T>(&self, filename: impl AsRef<Path>) -> T
where T: MartianMakePath,

Create a file in the files directory associated with the run. The correct extension is added depending on the return type.

use martian::{MartianRover, Resource};
use std::path::{Path, PathBuf};
let resource = Resource::new().mem_gb(2).threads(1).vmem_gb(5);
let rover = MartianRover::new("/some/path", resource);

// Note: The right extension is added for types which implement
// `MartianFileType` trait.

// You can also create a file with a custom name by using a
// PathBuf (preferred) or a String
let path_name: PathBuf = rover.make_path("bar.lz4");
assert_eq!(path_name.as_path(), Path::new("/some/path/bar.lz4"));

let file_name: String = rover.make_path("wl.txt"); // NOT Recommended. Prefer a PathBuf.
assert_eq!(file_name, String::from("/some/path/wl.txt"));

pub fn hard_link_or_copy<M: MartianFileType>( &self, src: &M, overwrite: bool, ) -> Result<M, Error>

Creates a hard link (falls back to copy) to the given MartianFileType file within the rover’s file directory, keeping the file name of src.

This is hard_link_or_copy_to with the file name of src as the destination name. Use hard_link_or_copy_to instead when several inputs may share a file name, for example the elements of an array input, since they would otherwise collide.

§Symbolic links

If src is a symbolic link (or a chain of them), the link is resolved first and the file it points to is hard linked or copied. The result in the rover’s file directory is therefore always a regular file, never a symbolic link, and it stays valid if the original link is later moved or deleted. The new file is named after src itself, not after the file that src points to: linking foo.txt, which points to data.txt, produces foo.txt. A link whose target does not exist is an error.

§Arguments
  • src - The path to the MartianFileType file. Symbolic links are followed, see above.
  • overwrite - What to do if a file with the same name already exists in the rover’s file directory. If true, the existing file is replaced. If false, an error is returned and the existing file is left untouched.
§Returns
  • The path of the newly created link

pub fn hard_link_or_copy_to<M: MartianFileType>( &self, src: &M, file_name: impl AsRef<Path>, overwrite: bool, ) -> Result<M, Error>

Creates a hard link (falls back to copy) to the given MartianFileType file within the rover’s file directory, under a new name.

The destination path is built the same way as make_path: the extension of M is added to file_name unless it is already there, so "counts" and "counts.csv" both produce counts.csv for a CSV file type.

file_name may include subdirectories, such as "vdj_t/clonotypes", as long as they already exist inside the rover’s file directory. It must be a relative path that stays inside that directory, so absolute paths and .. are rejected.

§Symbolic links

If src is a symbolic link (or a chain of them), the link is resolved first and the file it points to is hard linked or copied. The result is therefore always a regular file, never a symbolic link, and it stays valid if the original link is later moved or deleted. A link whose target does not exist is an error.

§Arguments
  • src - The path to the MartianFileType file. Symbolic links are followed, see above.
  • file_name - The name of the new file, relative to the rover’s file directory. The extension of M is added if missing.
  • overwrite - What to do if a file already exists at the destination. If true, the existing file is replaced. If false, an error is returned and the existing file is left untouched.
§Returns
  • The path of the newly created link
